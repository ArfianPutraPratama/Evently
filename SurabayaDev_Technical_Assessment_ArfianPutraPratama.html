📌 PART 1: TECHNICAL CASE STUDY

1. System Analysis

Berdasarkan skenario 3.000 user aktif dan 1.000 user melakukan pendaftaran serentak pada kuota tiket terbatas, analisis sistem mencakup:

A. Kebutuhan Fungsional per Role:
  • Peserta: Menjelajahi katalog event dengan pencarian instan, melihat status kuota real-time, mendaftar event (gratis/berbayar via simulasi QRIS & Virtual Account), dan mengunduh tiket digital ber-QR Code dengan tanda tangan kriptografis.
  • Panitia (Gatekeeper): Memindai QR Code tiket di gerbang masuk via kamera live/input manual, validasi instan (keaslian tanda tangan HMAC), tolak pemindaian tiket ganda, serta audit trail riwayat scan.
  • Admin: Manajemen penuh data event (CRUD), monitoring kuota terisi, rekap kehadiran aktual (*attendance rate*), serta analisa pendapatan tiket (*revenue analytics*).
B. Kebutuhan Non-Fungsional:
  • High Concurrency & Anti-Race Condition: Kuota tiket bersifat *hard-constraint*, tidak boleh terjadi *overselling* (tiket terdaftar > kuota) saat 1.000 request masuk bersamaan.
  • Integritas & Anti-Pemalsuan Tiket: QR Code tiket tidak boleh berupa ID biasa, melainkan memuat payload ber-tanda tangan digital HMAC-SHA256 berbasis secret key server.
C. Pembagian Tanggung Jawab:
  • Frontend: Validasi data di sisi klien, debounced search (300ms), state management reaktif, rendering QR Code SVG dinamis, feedback audio/visual gerbang presensi, dan pengalaman UX cetak PDF bersih.
  • Backend: Autentikasi berbasis token (Laravel Sanctum), otorisasi berbasis peran (Role-Based Access Control), orkestrasi transaksi basis data ACID dengan Pessimistic Row Locking, kalkulasi signature kriptografis, pencatatan log audit presensi, dan rate limiting API.

2. Frontend Perspective

  • Teknologi yang Digunakan: React 19 + TypeScript + Vite + Tailwind CSS + Lucide Icons + qrcode.react + canvas-confetti.
  • Struktur Komponen (Atomic Design):
    • Atoms: Button, Badge, Input, ProgressBar, StatusPill.
    • Molecules: SearchBar, QuotaIndicator, EventMetadata, AttendeeRow, PaymentMethodSelector.
    • Organisms: EventCard, EventDetailModal, RegistrationModal, TicketPassModal, CommitteeTerminal, AdminDashboard.
    • Templates/Views: CatalogView, MyTicketsView, GateScannerView, AdminConsole.
  • State Management: Scoped React Context (AuthContext) untuk autentikasi global & token sync dengan persistensi sinkron di localStorage (zero-flicker on refresh), didukung API service layer terisolasi.
  • Strategi Menjaga Performa:
    • Debouncing: Input pencarian diberi delay 300ms untuk menekan lonjakan request HTTP ke backend.
    • Tree Shaking & Code Splitting: Bundle produksi terkompilasi optimal via Vite bundler (total gzip ~192 kB).
    • Hardware Acceleration: Animasi modal dan transisi CSS memanfaatkan transform GPU.
    • Dynamic Endpoint Resolution: URL API mendeteksi domain/IP secara dinamis, mendukung localhost maupun Tailscale (100.117.102.84) tanpa re-build.

3. Backend Perspective

  • Desain Basis Data (PostgreSQL 18):
    • users: (id, name, email, password, role, phone, organization).
    • events: (id, title, slug, category, location, event_date, quota, registered_count, price, banner_url).
    • registrations: (id, event_id, user_id, registration_code, status, payment_status, payment_method, amount_paid) dengan Unique Index (event_id, user_id).
    • tickets: (id, registration_id, ticket_code, qr_payload, hmac_signature, status, checked_in_at, checked_in_by) dengan Unique Index ticket_code.
    • check_in_logs: (id, ticket_id, scanned_by, scan_result, ip_address, notes, created_at).
  • Pengelolaan Kuota & Anti-Race Condition:

    Menerapkan database transaction dipadu dengan Pessimistic Row Locking:

    DB::transaction(function () use ($eventId, $userId) {
    // Kunci baris event secara eksklusif
    $event = Event::where('id', $eventId)->lockForUpdate()->first();

    if ($event->registered_count >= $event->quota) {
        throw new HttpResponseException(response()->json(['message' => 'Kuota tiket sudah habis!'], 422));
    }

    $event->increment('registered_count');
    // Simpan pendaftaran & terbitkan tiket ber-HMAC
});

    Ketika 1.000 user mendaftar serentak, PostgreSQL mengeksekusi baris secara serial. User ke-1001 otomatis ditolak secara aman dengan HTTP 422 tanpa ada celah kuota bocor (*zero overselling*).

  • Pencegahan Duplicate Check-In:

    Saat panitia memindai tiket di pintu gerbang, sistem melakukan verifikasi atomik:

    $ticket = Ticket::where('ticket_code', $code)->lockForUpdate()->first();
if ($ticket->status === 'checked_in') {
    // Catat log pelanggaran dan tolak seketika
    CheckInLog::create(['ticket_id' => $ticket->id, 'scan_result' => 'duplicate_rejected']);
    return response()->json(['message' => 'Tiket sudah pernah digunakan!'], 409);
}
$ticket->update(['status' => 'checked_in', 'checked_in_at' => now(), 'checked_in_by' => auth()->id()]);

4. Technical Decision

A. Bagian Tersulit Sistem:
  1. High Write-Contention saat Perebutan Kuota: Terjadinya rebutan kunci baris basis data saat ribuan pendaftar mengakses event populer dalam milidetik yang sama.
  2. Gatekeeper Double-Scan Hazard: Kemungkinan dua panitia di dua gerbang berbeda memindai tiket yang sama (misal hasil screenshot WhatsApp) dalam waktu bersamaan.
B. Solusi Teknis yang Dipilih:
  • Pessimistic Locking vs Optimistic Locking (OCC): Kami memilih Pessimistic Row Locking (lockForUpdate) daripada OCC dengan version column. Pada kasus kuota tiket terbatas (*high write-contention*), OCC menghasilkan *retry storm* yang membebani CPU server. Pessimistic locking menjamin konsistensi mutlak dengan antrean serial di level database engine.
  • Tanda Tangan Kriptografis HMAC-SHA256: Menjamin integritas QR Code. Meskipun peserta mencoba memanipulasi isi JSON tiket, signature tidak akan cocok tanpa Server Secret Key.

🤝 PART 3: COMMUNITY COMMITMENT

1. Mengapa kamu tertarik bergabung menjadi bagian dari komunitas SurabayaDev?

SurabayaDev adalah pilar dan jangkar penggerak ekosistem teknologi di Jawa Timur selama 12 tahun terakhir. Konsistensi SurabayaDev dalam mengadakan workshop, seminar teknologi, dan mentoring telah menginspirasi banyak talenta digital, termasuk saya. Bergabung sebagai volunteer Divisi Developer Team adalah wujud nyata keinginan saya untuk mendedikasikan keahlian software engineering saya bagi komunitas, berkolaborasi dengan para praktisi hebat, serta berkontribusi langsung pada infrastruktur teknologi yang memberdayakan ribuan anggota komunitas di Surabaya.

2. Kontribusi apa yang ingin kamu berikan untuk perkembangan komunitas developer di Surabaya?

  • Pengembangan Infrastruktur Digital Komunitas: Merancang, memodernisasi, dan memelihara aplikasi internal SurabayaDev (portal event, sistem sertifikat otomatis, platform kurasi materi, dan bot interaktif).
  • Knowledge Sharing & Mentorship: Berbagi wawasan seputar best practices arsitektur modern (Full-Stack Architecture, TypeScript, API Scalability, Cloud Containerization, dan AI Agents) melalui tech talk maupun artikel teknis.
  • Inisiatif Open Source SurabayaDev: Membantu menginisiasi dan me-maintain repositori open source komunitas yang dapat menjadi wadah kontribusi nyata dan sarana belajar bagi mahasiswa/developer pemula di Surabaya.

3. Bagaimana cara kamu membagi waktu antara komunitas, kuliah/pekerjaan, dan aktivitas pribadi?

Saya menerapkan prinsip Time-Boxing dan Matriks Eisenhower secara disiplin:

  • Prioritas Utama (Pekerjaan/Studi): Diselesaikan secara fokus pada jam kerja formal (pagi hingga sore hari).
  • Dedikasi Komunitas: Mengalokasikan blok waktu khusus (6–10 jam per minggu di malam hari dan akhir pekan) yang konsisten dan terjadwal untuk tugas-tugas SurabayaDev.
  • Kolaborasi Async-First: Mengutamakan dokumentasi teknis yang jelas, tiket task yang terstruktur (GitHub Issues/Projects), dan komunikasi asinkron yang efektif sehingga tugas dapat diselesaikan tanpa hambatan birokrasi dan saling memblokir (*non-blocking*).

4. Apakah kamu bersedia tetap aktif berkontribusi setelah SurabayaDev 12th Anniversary selesai? Jelaskan bentuk kontribusi yang ingin dilakukan.

Ya, saya berkomitmen penuh untuk terus aktif berkontribusi pasca perayaan 12 tahun.

Bentuk kontribusi jangka panjang yang ingin saya jalankan meliputi:

  • Menjadi active maintainer dan pengembang fitur lanjutan pada platform digital SurabayaDev.
  • Membantu divisi acara dalam merancang kurikulum teknis dan hands-on lab untuk meetup bulanan SurabayaDev.
  • Berperan sebagai *onboarding mentor* bagi volunteer baru generasi berikutnya guna memastikan regenerasi komunitas berjalan berkelanjutan dan berkualitas.

5. Ceritakan pengalaman ketika bekerja dalam tim komunitas, organisasi, atau project open source.

Saya memiliki pengalaman berkolaborasi dalam tim pengembangan perangkat lunak dengan alur kerja berbasis Git (GitHub Flow, Pull Requests, dan Peer Code Review). Dalam salah satu proyek tim, kami pernah menghadapi tantangan perbedaan opini terkait arsitektur basis data dan *merge conflict* pada modul pembayaran.

Melalui pendekatan komunikasi terbuka, diskusi teknis yang berfokus pada data/fakta, serta empati antar anggota tim, kami berhasil menyepakati arsitektur yang paling optimal dan menyelesaikan rilis tepat waktu. Pengalaman ini membentuk prinsip kerja saya bahwa keberhasilan engineering di komunitas tidak hanya ditentukan oleh kecakapan menulis kode, tetapi juga oleh komunikasi yang transparan, kerendahan hati untuk menerima masukan, serta komitmen terhadap visi bersama komunitas.
